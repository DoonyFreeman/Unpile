# Релиз и развитие open source

План · 9 октября 2026. Никакие репозитории, аккаунты, релизы и публикации сейчас не создавались.

## 1. Что заставляет скачать

Воронка: понятная демонстрация → страница проекта → заметная кнопка Download for macOS → установка без технической настройки → первый понятный сеанс → следующий разбор → отзыв/звезда/вклад.

Самый сильный аргумент — видимый сценарий и доверие к работе с файлами. Свайпы помогают объяснить продукт, но не компенсируют трудную установку и страх удаления.

Для GitHub-звёзд полезны ясный README, удобный релиз, честные ограничения и поддержка проекта. Число звёзд не гарантируется. Установка, завершённая полезная сессия и отсутствие потери данных важнее счётчика популярности.

## 2. Канал и упаковка

Первый канал: **бесплатная сборка в GitHub Releases без обязательной покупки Apple Developer Program**, с **Unpile-x.y.z-universal.dmg** как предполагаемым именем артефакта. Если Universal не подтверждён — отдельные чётко обозначенные сборки для проверенных архитектур. Полный исходный код и инструкция локальной сборки рядом.

DMG: приложение, ссылка Applications, короткая инструкция переноса. Без installer daemon и root-прав. Страница релиза: OS minimum, архитектуры, версия, список изменений, известные ограничения, checksum, ссылка на исходную ревизию и отчёт о проверках.

Не выдавать автоматически создаваемый GitHub Source code ZIP за готовую сборку. «Download for macOS» ведёт к DMG конкретного текущего стабильного релиза. Beta и stable визуально различимы.

В v1.0 обновление — вручную через страницу релизов. Не добавлять сетевые обращения в приложение ради статистики. Sparkle рассмотреть позже как отдельный проверяемый проект обновлений, с верификацией пакетов и отдельным раскрытием сетевого потока.

## 3. Бесплатный выпуск и дополнительная подпись

Разработка в Xcode, локальная сборка macOS-приложения и размещение готового DMG на GitHub не требуют обязательной покупки Apple Developer Program. По текущему решению пользователя первый выпуск делаем этим бесплатным путём. Не путать бесплатную разработку и бесплатное приложение для пользователей с отдельной услугой Apple по Developer ID/нотаризации.

Не путать отсутствие Developer ID с полным отсутствием code signature: для выбранной архитектуры и sandbox может использоваться бесплатная ad hoc/локальная подпись. Она не удостоверяет разработчика для Gatekeeper. Проверить её в технической пробе, включая обновление и сохранение доступа к контейнеру/bookmarks.

При скачивании сборки без Developer ID и нотарификации macOS может потребовать дополнительное подтверждение открытия; точный сценарий проверить на поддерживаемых версиях и описать по [инструкции Apple](https://support.apple.com/en-us/102445). Это допустимый явно раскрытый компромисс первого GitHub-релиза, а не основание требовать оплату или отложить полезный проект. Не отключать Gatekeeper целиком, не распространять команды снятия quarantine и не обещать отсутствие системных предупреждений.

Дополнительный будущий канал: Developer ID signing, Hardened Runtime, notarization и stapling по [документации Apple](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution), если владелец отдельно решит упростить первое открытие. Apple Developer Program платная; стоимость проверять тогда. Покупка сейчас не запланирована. Нотарификация не является App Review или гарантией отсутствия ошибок.

Проверка бесплатного релиза на чистой учётной записи/устройстве: скачанный браузером DMG, quarantine сохранён, копирование в Applications, фактический системный сценарий первого открытия, выбор Downloads, полный путь на синтетическом наборе, повторное открытие и обновление. Если в будущем добавляется нотарификация — отдельно проверять stapled ticket и offline-первый запуск.

## 4. Pipeline release candidate

1. Согласовать публичное имя, лицензию, owner/repo, bundle ID и поддерживаемую OS.
2. Выбрать candidate revision; build/test, code review, UI QA, smoke tests на целевых архитектурах.
3. Собрать release app без debug entitlement, применить необходимую бесплатную ad hoc/локальную подпись по проверенному workflow.
4. Подготовить DMG; проверить целостность code signature, установку, первое открытие без Developer ID и повторный запуск на поддерживаемых системах. Нотарификация/платный сертификат не входят в этот pipeline.
5. Получить SHA-256 финального уже обработанного артефакта. Не менять его после проверки и одобрения.
6. Подготовить release notes, screenshot/demo, точные инструкции установки и ограничения.
7. Представить конкретный review package: revision, DMG/checksum, проверки, owner/repo/tag, preview публикации.
8. После явного одобрения опубликовать согласованный артефакт в согласованный GitHub Release. Любые существенные изменения кандидата требуют повторной проверки/одобрения.
9. Проверить доступность DMG и ссылки Download; резервный предыдущий релиз и процесс отзыва проблемной версии.

Нельзя отправлять секреты Apple в репозиторий или выдавать signing secrets PR workflow. После создания CI документация должна описывать точную повторяемую сборку из source; побитовую воспроизводимость подписанного/notarized артефакта не обещать без доказательства.

## 5. Оформление репозитория

Предлагаемая лицензия — MIT, выбрать до внешнего распространения. Если используется чужой код/ассеты, сохранить обязательные notices и совместимость лицензий; не распространять чужие материалы как свои.

README на английском, README.ru.md как перевод. Верхняя часть:

- Имя и одна строка пользы.
- Короткая демонстрация 15–25 секунд на вымышленных файлах.
- Заметная Download for macOS, минимальная OS и архитектуры.
- Три точных тезиса: local processing, review before Trash, native macOS.
- Установка за несколько действий и объяснение доступа к папке.

Ниже: screenshots светлой/тёмной темы; реальные возможности и ограничения; различие Корзины и свободного места; build from source; roadmap; вклад; лицензия; acknowledgements. После полезного содержания — короткий ненавязчивый “If it helped you, a star helps others find it”. Не блокировать скачивание просьбой о звезде.

Community health: CONTRIBUTING.md, SECURITY.md с приватным каналом сообщения о рисках, CODE_OF_CONDUCT.md при создании сообщества, CHANGELOG.md, шаблоны bugs/features, label good first issue для действительно небольших задач. Не просить screenshots реальных Downloads и полный пользовательский лог по умолчанию.

Topics только по факту: macos, swift, swiftui, downloads, file-management, open-source. Добавить GitHub social preview с короткой пользой и безопасной синтетической карточкой.

## 6. План запуска

| Когда относительно готовности | Действие | Условие |
| --- | --- | --- |
| До большой разработки | Интервью и два UI-направления | Добровольное исследование, без сбора файлов |
| До публичной beta | 5–10 пользователей Mac на проверенной сборке | Пройден этап безопасности; честный статус beta |
| За неделю до stable | Финальный demo, README, релиз-кандидат | Работает установка, известны ограничения |
| День stable | Публикация одобренного GitHub Release | Конкретный revision/артефакт одобрены |
| Следующие несколько дней | По одному релевантному посту в выбранных сообществах | Проверить актуальные правила и отдельно согласовать публикацию |
| Через 1–2 недели | Исправления по первым отзывам, update changelog | Реальная польза, без повторения одного рекламного текста |
| Через месяц | Оценить пользу и стоимость поддержки | Решения по наблюдаемым проблемам, не по обещаниям роста |

Каналы-кандидаты: r/macapps/r/opensource/r/SideProject, Show HN, сообщества macOS/Swift, личные соцсети и короткая видео-демонстрация. Product Hunt — когда продукт стабильно устанавливается и есть время отвечать. Правила площадок меняются; перечень не является разрешением публиковать или гарантией охвата.

Формат поста: реальная проблема → короткое demo → точное объяснение ручного выбора и Корзины → source/download → один содержательный вопрос об опыте разбора. Не выдумывать download numbers, отзывы, скорость, уникальность и «found X GB»; не покупать звёзды, не делать массовые личные сообщения и не спамить одинаковыми постами.

Короткое видео может показывать: большой installer → просмотр → отметка; важный PDF → оставить; неоднозначный файл → позже; отмена; список проверки; перенос. Все названия и содержимое — вымышленные.

Никаких постов, писем авторам обзоров или сообщений в сообщества от имени пользователя без отдельной явной инструкции. Сейчас планируются материалы, а не отправка.

## 7. Метрики без встроенного слежения

| Метрика | Источник | Ограничение |
| --- | --- | --- |
| Скачивания DMG по версии | GitHub release asset download_count | Это загрузки, а не уникальные установки; боты и повторные скачивания возможны |
| Звёзды и forks | GitHub | Интерес к проекту, не доказательство пользы приложения |
| Прошли установку и сеанс | Добровольный пилот/опрос | Небольшая выборка, самоотбор |
| Время и ошибки при разборе | Контролируемый пилот с согласием | Синтетические задания не равны повседневной работе |
| Серьёзные ошибки и время реакции | Issues/private security reports | Требуется ручной разбор и очищенные данные |
| Возврат при следующем накоплении | Добровольные повторные интервью | Нет автоматической retention-аналитики |

GitHub предоставляет [download_count для release assets](https://docs.github.com/en/rest/releases/releases?apiVersion=latest). Для первых 30 дней ориентир по результату: 10 развёрнутых отзывов, подтверждённая установка на заявленных Mac, исправленные серьёзные проблемы. Цели по звёздам ставить после первых реальных данных, не обещать «1 000 звёзд за неделю».

## 8. Поддержка и следующая версия

Назначить владельца релизов и публично понятный режим поддержки. Критические риски потери файлов и проблемы установки получают приоритет; при подтверждённом риске остановить выдачу проблемного бинарника, сообщить затронутые версии и способ безопасного продолжения.

Небольшие регулярные bugfix-релизы, changelog по пользовательскому результату, ограниченный roadmap. Подходящие первые contributions: переводы, воспроизводимые accessibility issues, fixtures, проверка совместимости и документация. Добровольные пожертвования/Sponsors можно добавить после появления полезного стабильного релиза; основная утилита остаётся бесплатной.

После v1.0 по спросу: несколько локальных папок, перенос в выбранные папки с отдельной Undo-моделью, безопасная обработка папок, встроенное восстановление с конфликтами и проверкой доступа, Homebrew-канал после проверки его актуальных требований, проверяемое автообновление. Поиск дубликатов — только как отдельная значимая задача. AI и «чистка всего Mac» не требуются для развития этой идеи.

Успех: люди доверяют приложению, завершают реальный разбор и рекомендуют его. GitHub-звёзды помогают распространению, но не заменяют этот результат.
