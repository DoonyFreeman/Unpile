# Продуктовый план

Версия концепции: 0.1 · 9 октября 2026. Предлагаемые решения для обсуждения; реализация и публикация в эту задачу не входят.

## 1. Что делаем

**Небольшую бесплатную утилиту для macOS, которая помогает разобрать Downloads по одному файлу за раз, начиная с крупных, и безопасно убрать ненужное в Корзину.**

Рабочее имя — **Unpile**: убрать накопившуюся стопку. Перед выбором публичного имени проверить существующие приложения, репозитории, домены и ограничения на использование имени. «Tinder для файлов» оставить коротким объяснением механики, а публичный бренд сделать самостоятельным.

Предлагаемая формулировка для англоязычного README: **“Clear your Downloads, one decision at a time.”** Дополнение: **“Preview. Keep. Review. Trash.”**

Обещание пользователю: «Вместо длинного списка — один понятный файл и одно решение. Можно остановиться в любой момент». Не обещать конкретное количество освобождённых гигабайт или улучшение скорости Mac.

Критически важное различие: перенос в Корзину обычно сохраняет данные на диске. Показываем «Выбрано для Корзины» и «Перемещено в Корзину», а не «Освобождено». Простое сложение размеров файлов не измеряет реально возвращённое свободное место: есть APFS, клоны, жёсткие ссылки, sparse-файлы и снимки.

## 2. Для кого и в каких обстоятельствах

| Аудитория | Ситуация | Нужный результат |
| --- | --- | --- |
| Обычный пользователь Mac | В Downloads сотни файлов; страшно удалить нужное | Разобрать небольшую часть без усталости и сюрпризов |
| Дизайнер, создатель контента | Остались большие видео, картинки, архивы | Быстро увидеть крупные кандидаты и их содержимое |
| Студент, офисный пользователь | Смешались документы, материалы и установщики | Узнать нужное по превью, отложить сомнительное |
| Пользователь с небольшим SSD | Требуется место для конкретной задачи | Сначала проверить крупные файлы, затем самостоятельно очистить Корзину |

Основная работа пользователя: «Когда Downloads переполнена, помоги мне понять, что ещё нужно, и убрать лишнее, чтобы я не боялся ошибиться и не тратил вечер на сортировку».

Это эпизодическая утилита. Ежедневное открытие не является целью. Возвращаться при следующем накоплении файлов — нормальная модель использования.

Проверено по первичным источникам 9 октября 2026:

| Альтернатива | Что уже решает | Наш предполагаемый акцент |

| [DClutter](https://github.com/RokiTheWise/DClutter) | Разбор файлов карточками, свайпы, клавиатура, проверка перед Корзиной | Короткие сессии вокруг крупных файлов и выразительный нативный интерфейс. Наличие спроса ещё нужно проверить |
| [DaisyDisk](https://daisydiskapp.com/guide/4/en/TipsAndTricks/) | Карта диска и поиск занимающих место файлов | Минимум навигации, решения в одной выбранной папке |
| [Hazel](https://www.noodlesoft.com/manual/hazel/work-with-folders-rules/create-edit-rules/) | Автоматизация обработки файлов правилами | Ручной выбор с превью без настройки правил |
| Finder | Сортировка, Quick Look, перенос в Корзину | Последовательный сценарий и сохранение незаконченного разбора |

**Свайпы, предварительный список и отмена не являются уникальными преимуществами.** Прямой аналог уже существует. Не представлять идею как первую в мире, не копировать чужой бренд, интерфейс или код без соблюдения лицензии.

Гипотезы отличия: быстрее добраться до значимого объёма кандидатов, проще завершить короткий сеанс, удобнее узнавать файлы по карточкам. Сравнить с Finder и DClutter в исследовании. Если отличия не дают ощутимой пользы, сократить объём или рассмотреть вклад в существующий проект вместо почти идентичной реализации.

## 4. Основной пользовательский путь

1. Скачать DMG, перенести приложение в Applications, открыть.
2. Увидеть короткое объяснение и выбрать Downloads в системном диалоге.
3. Выбрать «Крупные сначала» и короткую сессию до 20 файлов; есть вариант «Все файлы».
4. Смотреть превью и выбирать: оставить, отметить для Корзины, отложить.
5. При необходимости использовать Quick Look, открыть в Finder или отменить решение.
6. Закончить досрочно или дойти до конца выбранной сессии.
7. Проверить список кандидатов и подтвердить перенос в Корзину.
8. Увидеть результаты, включая ошибки, и при желании открыть системную Корзину.

Сессия ограничена количеством файлов, а не таймером: пользователь не должен спешить из-за обратного отсчёта. Нет обязательства разобрать всё, серии дней, рейтинга или давления «вы недостаточно очистили».

## 5. Юзкейсы и наблюдаемые критерии

| Сценарий | Поведение | Критерий |
| --- | --- | --- |
| Первый запуск | Системный выбор папки после объяснения | Нет запроса Full Disk Access, регистрации и установки CLI |
| Хочу быстрее найти большие файлы | Сортировка по убыванию логического размера | Крупные допустимые файлы показаны раньше мелких; критерий виден |
| Не узнаю документ | Миниатюра, метаданные, Quick Look | Можно разобраться без внешней загрузки содержимого |
| Хочу оставить | Файл остаётся на месте; решение запоминается для этой версии файла | При обычном повторном запуске тот же файл не мешает новой очереди |
| Не уверен | «Позже» исключает файл из текущей сессии | Файл остаётся доступным для следующей сессии и отдельного просмотра |
| Случайно выбрал удаление | Undo до подтверждения и исключение из списка проверки | Файл ещё не перемещён, отмена мгновенная |
| Хочу прекратить через 7 файлов | Досрочное завершение с проверкой кандидатов | Нельзя незаметно отправить кандидаты в Корзину при закрытии окна |
| Закрыл приложение | Сохранение очереди и решений | На запуске предложены продолжение или отмена незавершённого разбора |
| Файл изменился извне | Повторная проверка перед операцией | Изменённый или подменённый объект пропускается и требует нового решения |
| Часть операций не прошла | Показаны успехи и причины ошибок отдельно | Нет ложного сообщения, что вся пачка перенесена |
| Превью недоступно | Нейтральный тип файла и доступные метаданные | Работа продолжается, отсутствие превью не означает «ненужный» |
| Ничего не хочу удалять | Завершение без кандидатов | Позитивный нейтральный итог, без принуждения |

## 6. Объём первой публичной версии

Обязательное:

- Нативное окно macOS, светлая/тёмная тема, базовая доступность.
- Одна явно выбранная локальная папка, по умолчанию Downloads; работа только с обычными файлами верхнего уровня.
- Выбор папки и постоянный доступ через системные механизмы macOS.
- Асинхронное перечисление метаданных, понятная сортировка: крупные сначала, старые по дате изменения, имя.
- Сессия до 20 файлов либо вся доступная очередь. Остановка в любой момент.
- Карточка с именем, размером, типом, датой изменения, миниатюрой; Quick Look по запросу.
- «Оставить», «На удаление», «Позже»; кнопки и клавиатура; безопасный жест карточки.
- Undo решений до переноса, проверка списка, исключение отдельных кандидатов.
- Только системная Корзина, обработка частичных ошибок, итог.
- Продолжение незавершённой сессии после повторного запуска.
- Локальное хранение решений; повторный разбор ранее оставленных файлов и сброс истории решений.
- Английский интерфейс и русский перевод, документация по сборке и безопасности.
- Бесплатный DMG в GitHub Releases, проверенный на поддерживаемых Mac, с точным описанием первого открытия. Developer ID и нотарификация не являются обязательными расходами для v1.0.

Не входит в v1.0: очистка системных кэшей, удаление приложений, дубликаты, AI-классификация, рекурсивное удаление папок, перенос в пользовательские папки, облачные диски, сетевые тома, постоянный фоновый мониторинг, автоматическое удаление и очистка Корзины, автозапуск, сервер, аккаунт, встроенная аналитика, автоматическое обновление.

Папки и пакеты приложений показываются в сводке исключений и доступны через Finder. Симлинки, alias, незавершённые загрузки, placeholders облачных файлов и неподдерживаемые тома не включаются в разбор. Не обещаем определение всех файлов, которые сейчас используются другой программой.

Исключение по умолчанию для изменённых за последние 24 часа файлов — видимая настройка «Включить недавние»; это защита от свежих загрузок, а не доказательство, что старые безопасны.

## 7. Семантика решений

- **Оставить:** не перемещать; сохранить решение для идентичности и версии файла. «Показать оставленные» позволяет пересмотреть.
- **На удаление:** только локальное намерение. Любой перенос требует списка проверки и отдельного подтверждения.
- **Позже:** отложить до следующей сессии; не возвращать автоматически в конце текущей, чтобы не создавать бесконечный цикл.
- **Отмена:** отменяет последнее решение текущей сессии. Список проверки позволяет менять любые отметки.
- **После Корзины:** предложить «Открыть Корзину». Встроенное восстановление не обещать в v1.0: это отдельная сложность доступа и конфликтов имён. Системное восстановление возможно, пока объект остаётся в Корзине; наличие резервной копии приложение не проверяет.

Новое содержимое, замена объекта или изменение значимых метаданных обнуляют старое решение. Простое совпадение имени не даёт права считать файл прежним. При сомнении запрашиваем новое решение.

## 8. Безопасность и приватность

Выбранная папка может содержать документы, финансовые сведения и персональные данные, поэтому минимизация входит в архитектуру с первого дня.

| Данные | Зачем и откуда | Получатели/хранение | Срок и удаление |
| --- | --- | --- | --- |
| Доступ к папке и bookmark | Доступ, разрешённый системным диалогом | Только приложение, локальный контейнер | До смены/отключения папки; удалить при отзыве доступа в приложении |
| Имя, относительный путь, ID, размер, дата, тип | Очередь из выбранной папки | Локальная память; минимум полей в состоянии | Незавершённая сессия до завершения/отмены; устаревшие записи очищать при сверке |
| Превью содержимого | Узнать файл | Память приложения и системные компоненты просмотра macOS | Собственный кэш только в RAM; после сессии удалить; системные кэши контролирует macOS |
| Решение и версия объекта | Не спрашивать каждый раз, продолжить сеанс | Локальный контейнер | Оставленные — до пересмотра, изменения или сброса; успешные кандидаты после переноса удалить из активного состояния |
| Итог переноса | Объяснить результат и ошибки | Память; минимум статуса для восстановления после сбоя | Подробный завершённый журнал не хранить постоянно; сохранять только нерешённые операции |
| Диагностика | Поиск ошибки | Локально: код ошибки и компонент, без имён, путей, bookmark и содержимого | Ограниченный локальный журнал; очищается, отправка пользователем только после просмотра |
| Скачивание релиза | Получение приложения | GitHub и браузер пользователя | Политики платформы; приложение не добавляет собственный профиль пользователя |

Не читать историю браузера, источник загрузки с URL/query-параметрами, Finder-комментарии и содержимое для аналитики. Не делать хэши всех файлов ради несуществующей функции дубликатов. Не встраивать сторонние трекеры. Не отправлять автоматические crash reports с пользовательскими путями.

Для HTML, SVG, скриптов и исполняемых файлов показывать безопасную карточку метаданных, без собственного WebView и автозапуска. Превью ограничить проверенными типами: изображения, PDF, локальные медиа. Quick Look и встроенные сторонние системные расширения нельзя описывать как полностью подконтрольные приложению; документировать эту границу.

Границы: никакой записи за пределы разрешённой папки, кроме собственного контейнера и системного механизма Корзины. Нет permanent-delete fallback, команд shell с путями пользователей и привилегированного helper. Ошибка доступа останавливает затронутую операцию.

## 9. Проверка пользы до большой разработки

1. Пять коротких интервью с людьми, у которых Downloads накопилась естественным образом. Выяснить последний реальный случай разбора, страхи и критерии решения; не просить копировать их файлы в исследование.
2. Проверить два макета на одинаковом синтетическом наборе из 20 файлов: карточка с фокусом на превью и карточка с видимой очередью.
3. Сравнить с Finder; порядок заданий менять, чтобы не спутать обучение с преимуществом интерфейса.
4. Проверить понимание «Оставить», «Позже», отмены и Корзины. Наблюдать способность закончить досрочно.
5. Спросить, в какой следующей реальной ситуации человек открыл бы приложение; избегать вопроса «вам нравится идея?».

Предварительные цели для небольшого пилота, а не доказанная статистика: 4 из 5 участников без подсказки проходят путь до проверки; все понимают, что свайп ещё не удаляет; ни одной непреднамеренной операции над файлами. Если интерфейс медленнее Finder или не снижает путаницу, переработать до запуска.

Измерять вручную с согласия участников: время до первого решения, время на набор файлов, возвраты/ошибки, завершённый сеанс и субъективное доверие. Содержимое и имена реальных файлов не собирать.

## 10. Решения и открытые вопросы

Рекомендации: SwiftUI + AppKit, локальная работа, macOS 14+ как предварительная нижняя граница, Universal для Apple Silicon и Intel, MIT как предлагаемая лицензия, GitHub Releases как первый канал. Совместимость подтвердить сборкой, а имя и лицензию выбрать до публикации.

Перед реализацией: подтвердить пользу отличий от аналога, развить выбранный пользователем «Обзор» в стилистике macOS 27 / Liquid Glass, зафиксировать минимальную macOS после технической пробы. До публичного выпуска: определить GitHub owner/repo и bundle identifier; проверить упаковку и первый запуск бесплатной сборки. Покупка Apple Developer Program не требуется по текущему плану; Developer ID/нотаризацию обсуждать отдельно только при необходимости. Сейчас покупать, регистрировать или публиковать ничего не требуется.

Главные риски: усталость от сотен карточек, потеря доверия при первом запуске, ошибочное объяснение освобождённого места, гонки при изменениях файлов, трудности sandbox/Корзины, неподдерживаемое железо, отсутствие времени на поддержку. Меры и этапы проверки описаны в плане реализации и релиза.
