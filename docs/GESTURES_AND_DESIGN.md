# Свайпы и экран разбора · beta 0.6

## Поведение

Курсор должен находиться над видимой карточкой. Два пальца двигаются горизонтально без нажатия: влево — «На удаление», вправо — «Оставить». Решение принимается после отпускания. Короткое движение, возврат ниже порога, отмена системой или потеря фокуса возвращают карточку на место. Вертикальное/диагональное начало фиксирует прокрутку и не превращается в решение посреди движения.

Natural Scrolling нормализуется к направлению пальцев. Инерция, обычные wheel ticks без gesture phase и продолжение старого жеста на новой карточке не принимают решения. Совместимые phased precise scroll устройства могут передавать такие же события; приложение не измеряет число физических пальцев.

Жест меняет только решение: файл остаётся на месте. Перенос по-прежнему требует проверки списка и отдельного подтверждения. Во время превью, настроек, выбора папки, подтверждения, ошибки и выполнения переноса жесты не меняют скрытый разбор. Кнопки, клавиатура и mouse drag доступны параллельно.

## Оформление

- Стопка из трёх слоёв, более компактное превью и мягкий фон с cyan/indigo accents.
- Карточка следует за горизонтальным движением, меняет обводку и показывает цветную метку действия. При достижении порога появляется «Отпустите, чтобы выбрать».
- При отмене карточка возвращается с spring animation; следующая появляется с мягким переходом.
- Три крупные glass-кнопки закреплены под областью прокрутки. В компактном окне видны действия и список кандидатов; карточка прокручивается отдельно.
- Reduce Motion убирает перемещение/поворот/масштабирование, оставляя цвет и подпись. Reduce Transparency сохраняет непрозрачный fallback для glass controls.

## Реализация и локальные данные

SwiftUI DragGesture обслуживает mouse drag. Для тачпада AppKit local event monitor получает только события этого приложения; область ограничена окном и видимой карточкой. Глобального мониторинга и дополнительных разрешений Accessibility/Input Monitoring нет. По [документации Apple](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/HandlingTouchEvents/HandlingTouchEvents.html), двухпальцевое перемещение приходит как scroll event с фазами; momentum отделён от физического движения. [Настройка инверсии](https://developer.apple.com/documentation/appkit/nsevent/isdirectioninvertedfromdevice) учитывается отдельно.

Используются delta X/Y, phase, признак precise scrolling, настройка инверсии, положение события относительно карточки и её session ID. Эти значения нужны для распознавания решения, живут в RAM до конца/отмены жеста и не сохраняются, не логируются и не передаются третьим сторонам. Точки касания и идентификаторы устройства не собираются. Само принятое решение сохраняется по существующим правилам [LOCAL_DATA.md](LOCAL_DATA.md); демо остаётся в RAM.

`CardSwipe` — чистый reducer; AppKit bridge управляет eligibility/lifecycle, а модель повторно сверяет ID текущего файла перед принятием. Monitor удаляется при отсоединении native view. Порог 23% ширины карточки, ограниченный 80–130 pt; решение не зависит от скорости flick.

## Проверка

Пять автоматических сценариев: направление при обоих scroll preferences, вертикальные/неполные последовательности, отмена/реверс/короткое движение, одна операция без повторения через momentum, отклонение coarse/non-finite input. Вместе с существующими проверками — 27.

Локально осмотрены обычное и компактное окно, mouse drag, короткий drag, Undo, вертикальная прокрутка и блокировка клавиш/прокрутки в preview. 11 октября 2026 пользователь подтвердил работу обоих двухпальцевых свайпов в демо финальной копии 0.6.0: вправо — «Оставить», влево — кандидат. Это пользовательская проверка настоящего тачпада; автоматические потоки событий и mouse drag учитываются отдельно.

Полный ручной проход ещё нужен: короткий жест, инерция после flick, вертикальная прокрутка, оба значения Natural Scrolling и блокировка жестов в preview/settings. Подтверждение двух направлений не закрывает эти сценарии.

Для ручного прохода открыть демо, поставить курсор над изображением карточки, выполнить вправо/влево без клика, отменить через Undo, проверить короткий свайп и вертикальную прокрутку. Длинный flick должен выбрать один файл; оставшаяся инерция не должна выбрать следующий. Затем повторить с другим Natural Scrolling preference и с открытыми preview/settings.
